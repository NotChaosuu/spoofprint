## Section 2 — TLS ClientHello per browser, 2026

### 2.1 Cipher suites
TLS 1.3 core (0x1301/0x1302/0x1303) common to all four majors + shrinking TLS 1.2 ECDHE tail. Chromium puts a GREASE codepoint at cipher position 0 (RFC 8701). https://www.rfc-editor.org/rfc/rfc8701.html · https://scrapfly.io/web-scraping-tools/ja3-fingerprint

### 2.2 Extension order + GREASE
- **Chrome permutes extensions per-connection since Chrome 110 (Jan 2023)**, subject to RFC 8446 (pre_shared_key stays last). ~16 randomizable → 16! ≈ 2.09e13 JA3 hashes. https://www.fastly.com/blog/a-first-look-at-chromes-tls-clienthello-permutation-in-the-wild
- **Firefox does NOT permute** (bugzilla 1789436 open). https://bugzilla.mozilla.org/show_bug.cgi?id=1789436
- Edge inherits Chromium permutation. Safari no randomization; exact 26.6 layout **UNVERIFIED**.
- Consequence: **classic JA3 is dead for Chrome/Edge**; only sorted-input hashes (JA4/JA4_ro) survive.

### 2.3 supported_versions
All four advertise TLS 1.3 (0x0304) + TLS 1.2 (0x0303). No 2026-dated removal plan surfaced (**UNVERIFIED**).

### 2.4 key_share + X25519MLKEM768 (0x11EC) — the strongest signal
Strongest positive ID of a real 2026 browser; its ABSENCE is the strongest spoof tell.
- **Chrome:** default since 131 (Nov 2024); precursor X25519Kyber768Draft00 in 124. https://blog.cloudflare.com/pq-2025/
- **Firefox:** default in 132 for HTTPS (Nov 2024); QUIC/H3 added in 135.
- **Safari:** default in iOS/iPadOS/macOS Tahoe 26 (fall 2025) at URLSession/Network layer; 0x11EC first, X25519 second, both key_shares pre-computed. https://support.apple.com/en-us/122756
- **Edge:** inherits Chromium 150.

Adoption (Cloudflare edge mid-2026): >60% of human HTTPS uses X25519MLKEM768 (Q1–Q2 2026). Origin-side 9.58% Q2 2026. Top-100k origins w/ PQ TLS: 39% (Sept 2025). https://blog.cloudflare.com/radar-origin-pq-key-transparency-aspa/

### 2.5 signature_algorithms
Common: ecdsa_secp256r1_sha256 (0x0403), ecdsa_secp384r1_sha384 (0x0503), rsa_pss_rsae_sha256/384/512 (0x0804/5/6), rsa_pkcs1_sha256/384/512 (0x0401/5/6), ed25519 (0x0807 FF+Safari). Chrome keeps sha1 TLS1.2 fallback. Full per-browser 2026 enumeration **UNVERIFIED** — build the reference table from Wireshark captures, not write-ups. Live probes: https://tls.peet.ws/api/all · https://tlsfingerprint.io/

### 2.6 ALPS / application_settings
- ext 17513 = ALPS v1; ext 17613 = ALPS v2 (current Chromium). https://vasilvv.github.io/tls-alps/draft-vvv-tls-alps.html
- Chrome/Edge only — Firefox + Safari don't emit it → presence = strong Chromium tell.
- Whether Chrome 151 emits only 17613 or both **UNVERIFIED**.

### 2.7 ECH
- **RFC 9849 published 2026-03-03.** https://packet.guru/blog/ECH-Encrypted-Client-Hello-2026
- Chrome default-on since 122 (w/ DNS HTTPS RR). Firefox default-on since 118. Safari 26.6 **UNVERIFIED**.
- Server-side: 4.2% Tranco top-10K, 9.2% top-1M advertise ECHConfig (Feb 2025); 51% of TLS1.3 servers parse ECH. Cloudflare free zones default-on; Fastly/Akamai followed 2024.
- Implication: score on the OUTER ClientHello (what the server sees); treat ECH-outer templates as their own family.

### 2.8 Certificate compression (RFC 8879, ext 27)
Chrome brotli-only since 69. Firefox Nightly brotli/zlib/zstd; FF 153 stable **UNVERIFIED**. Edge presumed brotli (Chromium).

## Section 3 — HTTP/2 fingerprint per browser, 2026

Format: `SETTINGS|WINDOW_UPDATE|PRIORITY|pseudo-order` (Akamai shorthand, unchanged since 2017). https://www.blackhat.com/docs/eu-17/materials/eu-17-Shuster-Passive-Fingerprinting-Of-HTTP2-Clients-wp.pdf

### 3.1 Chrome (151)
SETTINGS: HEADER_TABLE_SIZE=65536, ENABLE_PUSH=0, MAX_CONCURRENT_STREAMS=1000, INITIAL_WINDOW_SIZE=6291456, MAX_FRAME_SIZE=16384, MAX_HEADER_LIST_SIZE=262144. WINDOW_UPDATE=15,663,105. Pseudo `m,a,s,p`. **Chrome no longer emits RFC7540 PRIORITY — uses RFC 9218 Extensible Priorities (priority header + PRIORITY_UPDATE) since Chrome 105.** Sample: `1:65536;2:0;4:6291456;6:262144|15663105|0|m,a,s,p`. https://datatracker.ietf.org/doc/html/rfc9218 · https://scrapfly.io/blog/posts/http2-http3-fingerprinting-guide
Conflict: Scrapfly says Chrome 119+ omits SETTINGS ids 3+5; Sendwin 2026 sends all six. **UNVERIFIED — capture live.**

### 3.2 Firefox (153)
SETTINGS (research): HEADER_TABLE_SIZE=65536, ENABLE_PUSH=0 (push removed FF132), MAX_CONCURRENT_STREAMS=100, INITIAL_WINDOW_SIZE=131072, MAX_FRAME_SIZE=16384, MAX_HEADER_LIST_SIZE=65536. WINDOW_UPDATE 12,451,840 (Sendwin) / 12,517,377 (Scrapfly). Pseudo `m,p,a,s`. https://blog.crawlex.net/blog/http2-priority-dependency-fingerprint/

Capture shows real FF 153 sends 4 SETTINGS (`1:65536;2:0;4:131072;5:16384`) and a single HEADERS priority with a varying weight (`3:0:0:42`), not a dependency tree. The shipped profile uses the captured values.

### 3.3 Safari (26.6)
(last public detail was Safari 18; 26.6 exact **UNVERIFIED**): HEADER_TABLE_SIZE=4096, ENABLE_PUSH=0, MAX_CONCURRENT_STREAMS=100, **INITIAL_WINDOW_SIZE=65535 (RFC default — the standout Safari signature)**, MAX_FRAME_SIZE=16384, MAX_HEADER_LIST_SIZE not sent. Pseudo `m,s,p,a`. Exclusive-dep priority, default weight 16.

### 3.4 Edge (150)
No source separates Edge from Chrome at this layer; assume byte-identical. https://github.com/fingerprintjs/fingerprintjs/issues/756

### 3.5 Changes since Chrome 131
H2 server push dead everywhere (Chrome 106 disabled, FF 132 removed code, Safari/Edge advertise 0). RFC 9218 priorities replace RFC 7540 in Chrome. WebTransport rides H3 not H2.

## Section 4 — HTTP/3 / QUIC, 2026

### 4.1 Client default
Chrome H3 default since ~87. Firefox default-on; Nightly 154 (2026-06-15) added QUIC v2 (RFC 9369), stable timeline **UNVERIFIED**. Safari default since 18.5 but only when DNS HTTPS/SVCB RR advertises. Edge inherits Chromium.

### 4.2 Server
Cloudflare default. GFE default. CloudFront opt-in per distribution (since 2022-08). Fastly edge-enabled. Akamai per-property, global default **UNVERIFIED**.

### 4.3 Adoption
H3 ≈ 21% (Cloudflare 2025 YIR; Radar April 2026 = 21.11%), down from 28% peak May 2023. https://blog.cloudflare.com/radar-2025-year-in-review/

### 4.4 QUIC CH vs TLS 1.3 CH
Same TLS 1.3 ClientHello in CRYPTO frames → JA3/JA4 work. Extras: transport params (ext 0x39), ALPN h3, Initial padded ≥1200B, version_information (RFC 9368).

### 4.5 QPACK
QPACK_MAX_TABLE_CAPACITY (0/4096/65536), QPACK_BLOCKED_STREAMS (~100). Per-browser 2026 values **UNVERIFIED** — capture via nghttp3/mitmproxy 10.

### 4.6 QUIC transport params (fingerprintable, RFC 9000 §18)
initial_max_data, initial_max_stream_data_bidi_local/remote/uni, max_idle_timeout, initial_max_streams_bidi/uni, active_connection_id_limit, disable_active_migration, max_ack_delay, ack_delay_exponent, max_udp_payload_size, version_information, GREASE params. Chrome ref: initial_max_data ≈15MB, bidi_local/remote=6291456, max_idle_timeout=30000ms. FF/Safari/Edge exact **UNVERIFIED**.

### 4.7 Spin bit / migration
Spin bit opt-in per impl (**UNVERIFIED** per browser). disable_active_migration=1 fingerprintable, common on mobile Safari (**UNVERIFIED** 26.6). Retry token = server-issued, not client fp.

### 4.8 QUIC v2 (RFC 9369)
FF Nightly 154 has it. Chrome/Safari/Edge stable + CDN server defaults **UNVERIFIED**.

## Section 5 — JA4+ family (July 2026)

### 5.1 Roster
JA4, JA4S, JA4H, JA4L, JA4LS, JA4X, JA4SSH, JA4T, JA4TS, JA4TScan, JA4D, JA4D6 + JA4one variant. JA4D (DHCP) added Nov 2025. https://github.com/FoxIO-LLC/ja4 · https://zeek.org/2026/01/how-to-use-ja4-network-fingerprints-in-zeek/
No JA4H3/JA4Q — QUIC folded into JA4 via `q` prefix.

### 5.2 JA4 (TLS) spec
Unchanged since 2024: `(q|d|t)(TLSver)(SNI d|i)(cipher count)(ext count)(ALPN first+last) _ sha256(sorted ciphers,12) _ sha256(sorted exts + sigalgs,12)`. e.g. `t13d1516h2_8daaf6152771_b186095e22b6`. **~36 chars — the "22-char" claim in the brief is wrong.** Sorting defeats Chrome permutation. https://github.com/FoxIO-LLC/ja4/blob/main/technical_details/JA4.md

### 5.3 Reference impls
FoxIO main last tag v0.18.8 (2024-11). Zeek plugin (Zeek 6+ for QUIC). Wireshark dissector in-tree (2026 = bugfix only). Suricata 8.0 has ja4.hash keyword. ja4-nginx-module v0.9.0-beta. Arkime full support.

### 5.4 LICENSING (critical for monetization)
- **JA4 (TLS) = BSD-3-Clause**, no patent claim.
- **All other members = FoxIO License 1.1, NON-COMMERCIAL only.** FAQ: "If a company uses JA4+ to provide value to paying customers, even without exposing JA4+ fingerprints directly, that company would still need an OEM license." Internal defensive corporate use is fine. https://github.com/FoxIO-LLC/ja4/blob/main/License%20FAQ.md
- **Bottom line:** ship JA4-TLS freely; do NOT ship JA4S/JA4H/JA4T/JA4X in a paid product without OEM. spoofprint uses JA4H → design paid tier around it or negotiate.

### 5.5 Competing
JA3/JA3S unmaintained, broken by Chrome permutation. HASSH (SSH) still used. Akamai H2 fingerprint still de-facto. Peetprint/tls.peet.ws — endpoint down during scan (**UNVERIFIED**). TA3 dormant.

## Distilled design implications

1. **PQ key share = highest-leverage single check.** Claiming Chrome 131+/FF 132+/Safari 26+ without X25519MLKEM768 ≈ spoofed. Cheap, wide.
2. **JA3 dead for Chrome/Edge** — use JA4/JA4_ro sorted-hash.
3. **Firefox H2 priority** — a single HEADERS priority frame with a varying weight, not a dependency tree, so it's too noisy to match on and is excluded.
4. **Safari INITIAL_WINDOW_SIZE=65535** — Safari's H2 signature.
5. **utls has gaps** — cross-ref bogdanfinn/tls-client presets + real Wireshark captures before shipping profiles.
6. **JA4+ license forbids commercial resale beyond JA4-TLS** — design paid product around it.
7. **Chrome uses RFC 9218 priorities, not RFC 7540 PRIORITY** — stale training data gets this wrong.
8. **H3 fingerprint tuning immature in Go** — uquic + tls-client v1.14+ + req v3.59; novel work, defer to v0.2.
9. **Competitive gap is real** — no OSS Go scorer with spoofprint's pitch.
